# 游戏展会一图流

个人使用的游戏发布会海报编辑器，React + Vite，默认输出 1440 × 1920 PNG，也可导出长图或全部页面 ZIP。可静态部署用于本机编辑，也可部署私人同步服务实现登录与跨设备同步。

## 本地运行

使用 Node.js 24（仓库提供 `.nvmrc`；最低支持 Node 22.12）。

```bash
npm ci
npm run dev
```

打开终端显示的本机地址。检查代码：

```bash
npm test
npm run build
```

## 保存和备份

- 编辑后自动将完整项目保存到当前浏览器的 IndexedDB，包括上传的图片、自定义主题和文字设置。
- 顶部「保存项目」保存到私人服务器；「备份 → 保存本机副本」仅保存此浏览器并增加一条本机恢复记录，最多保留 12 条。
- “下载项目备份”生成 ZIP，包含项目文字、本地图片和自定义主题；“导入项目备份”可在另一浏览器、电脑或域名恢复，也支持旧版项目 JSON。导入时默认载入为独立草稿，再填写名称保存到云端；只有明确选择带项目名的替换按钮才更新当前项目。两种方式都会先备份当前本机内容。
- 网络图片链接原样保留，备份不下载网络图片。内置 Logo 使用应用自带资源。
- 浏览器数据被清理后，本地项目可能丢失，请定期下载 ZIP 备份。退出前应等待“已保存到此浏览器”；未保存完会触发浏览器离开提醒。
- 同一网站只允许一个标签页编辑，避免互相覆盖。后开的页面会提示先关闭另一个编辑页面。
- 首次升级会读取旧版 localStorage 草稿和主题；旧版已经丢弃的图片不能自动找回。启动不再自动用线上模板覆盖本机草稿。

限制：每项目最多 1000 款游戏，本地图片单张 20 MB，项目图片总量 100 MB。裁剪图片最大 1472 × 828；长图超过 16000 像素时请使用分页 ZIP。保存失败时可下载项目备份。仅支持具备 IndexedDB、Web Locks、Web Crypto 的现代浏览器，请使用 HTTPS 或 localhost。

## 按游戏名选择 IGDB 图片

登录私人同步网站后，打开卡片，在「文字」里填写游戏名，停顿约 700ms 自动匹配；切换「配图」查看候选。候选显示游戏名、年份和平台；确认游戏后可浏览截图、宣传图和封面，选择图片后进入 16:9 裁剪。只有确认裁剪才替换图片。搜图关键词可以单独改成英文或别名，不会改动卡片标题；原上传、拖入和粘贴图片仍可使用。

IGDB 的中文别名和本地化资料不一定完整。精确原名/别名匹配优先，同等条件优先官方游戏，Mod 与同人作品仍作为备选。图片导入为项目内嵌素材，连同 IGDB 来源记录一起保存和同步，后续导出不依赖 IGDB 图片链接。

凭据只配置在后端（见 [服务器说明](server/README.md#igdb-游戏选图)），静态 GitHub Pages 不具备该服务。iPhone App 0.2.0 提供同样的原生搜图与确认导入功能。

## 批量导入

支持书名号标题和“游戏名称：”标题。先按游戏划块，再提取日期、平台和说明。例如：

```text
《游戏甲》
发售日期：2026年9月24日
登陆平台：PS5 / PC
现已开启预购，Steam国区售价268元

《游戏乙》
发售日期：待公布
登陆平台：Switch 2
支持试玩
```

可替换或追加列表，随后使用拖拽、键盘拖拽或上下移动按钮调整顺序。撤销按钮作用于项目；输入框内的 Ctrl/Cmd+Z 保留浏览器原生文本撤销。

## 编辑界面

顶部工具栏固定显示撤销、保存、备份和导出。保存状态明确显示“已保存到此浏览器”和时间；编辑区上方的“账号与同步”单独显示云端状态。

## 私人网站与跨设备同步

部署方式见 [server/README.md](server/README.md)，使用 Node.js 24 或以上，前端与 API 同源。首次使用一次性设置令牌创建个人账号，之后使用用户名、密码登录。服务端仅允许一个账号。

日常流程是「创建项目 → 选择模板 → 编辑 → 保存项目 → 服务器历史项目」。创建时先命名并选择内置、自定义或共享模板，然后进入空白卡片草稿；首次点击顶部「保存项目」后才会存入服务器历史，后续编辑继续自动同步。首次保存保留当前卡片与撤销记录。历史窗口只展示服务器项目的名称、模板、卡片数和保存时间，可搜索并重新打开返工。

左侧为紧凑卡片目录；点击卡片或海报后，独立编辑面板提供「文字」「配图」「日期与平台」三个分类。宽屏同时显示目录、预览和编辑面板，窄屏通过完成编辑返回目录。模板排版、批量导入和本机恢复记录通过不同工具页进入，不再堆叠在卡片列表中。

模板保存可复用外观；项目保存一次作品的完整文字、图片和排版。历史窗口的「管理当前项目」提供重命名、复制、命名版本及恢复旧版本。切换项目前会先保存修改并备份本地内容，网络错误或冲突时暂停；复制建立独立副本，已同步到原项目的修改不会撤回。切换项目会清空撤销栈，避免撤销到另一项目。

新设备没有本机草稿时自动打开云端；本地内容一致或确认没有未同步修改时自动恢复。只有确有不同的本机草稿时才选择同步方向，未载入的云端候选不会标成当前编辑项目。另一设备的更新在空闲时约 15 秒内检查；并发编辑发生冲突会暂停上传并提示选择。“本项目版本”保留最近 20 个未命名版本及全部命名版本，与“历史项目”列表不同。填写“版本名称”并保存，可长期保留初稿、定稿等恢复点。离线时可继续编辑，恢复网络后重试；关闭页面前请等待云端显示“已同步”。本机历史记录带来源项目名称；恢复也默认成为独立草稿，避免把其他项目的历史写入当前项目。旧版单项目会自动保留为“State of Play（旧站导入）”，账号及全部图片保持原样。

从旧网址迁移：先在旧页面下载项目 ZIP 备份，再在新网址导入，登录并选择上传本机内容。不同域名的浏览器草稿不会自动迁移。服务端数据及图片保存在私有目录；部署文件、数据备份方法及恢复步骤见服务端文档。退出登录不会删除当前浏览器草稿，请只在可信设备使用。

- 游戏列表默认只展开当前条目；点击缩略图或名称切换编辑，支持收起。添加游戏会定位新条目。
- 点击预览中的游戏卡片，会定位对应编辑项并高亮；也可用 Tab、Enter 或空格选择。高亮仅用于编辑，不会出现在导出图片中。
- 每张卡片可独立关闭“显示发售日期”和“显示平台”，适合公告等非游戏内容。隐藏不删除原值，预览、分页测量、导出和项目备份都保留该设置；旧卡片默认显示。
- 常用平台用标签点选；其他平台输入后按 Enter 或“添加”。可移除所有平台，后续再补充。
- 游戏图片支持上传、拖入和粘贴截图，可替换、重新裁剪或移除。重新裁剪以当前图片为基础。
- 批量导入先显示识别结果，核对日期、平台后确认追加或替换；修改输入后需要重新预览，避免导入旧结果。
- 主题、排版、字体、署名和 Logo 分组折叠；手机通过“编辑内容 / 查看预览”切换工作区。
- “导出”菜单统一选择当前页、全部页面 ZIP 或长图。预览模式与导出格式可以分别选择。

## 导出与主题

预览随容器宽度缩放，导出保持原始尺寸。图片或字体加载失败会显示错误；超长单卡应减少文字、缩小字号或改用长图，避免静默裁切。导出时按需生成页面，并提供取消操作。

在“模板与排版”选择样式模板后，点击“复制当前模板”，即可从内置或自定义主题创建副本。副本保留原来的布局、颜色、主题文字及 Logo 位置和大小；修改名称与样式后保存，原模板不变，取消不会新增模板。字体和署名等项目级设置保持当前值。

“共享模板库”独立于项目：可将当前样式命名保存，并在其他已有项目或另一台设备应用。应用保留项目卡片、标题和署名文字；项目保留自己的样式副本，因此模板库后续变化不会改动旧稿。已有自定义主题在服务升级时迁移到共享库。

内置主题配置位于 `src/data/themes.js`，Logo 在 `public/logos/`，目录配置为 `src/data/logoLibrary.js`。自定义主题随本地项目、备份和线上发布完整保存。

## GitHub Pages 和可选线上发布

推送 main 后，GitHub Actions 运行测试、构建并更新 gh-pages。首次配置需准备 gh-pages 分支，并在仓库 Pages 设置中选择该分支。部署保留分支中的 `template.json`、`template-assets/` 和 `CNAME`。

默认项目站构建使用 `/Gameshow-Picmake/` 路径。仅在需要在线分享模板时，展开“线上发布”，填写目标仓库的 fine-grained PAT，点击“发布到公开 GitHub”。PAT 只保存在当前页面内存中，刷新后清除，旧版持久化 PAT 会被移除。

**线上发布会把文字和图片写入公开仓库和 Pages，不适合未公开资料。** 日常本地保存不需要 PAT。线上版本仅在点击“载入线上版本”后加载，载入前保存当前历史；请求期间发生新编辑会停止载入。点击发布后继续编辑不会被上传完成时的旧快照覆盖。

同步仓库配置仍位于 `src/utils/coreUtils.js`。不要把 PAT 写入源码、Vite 环境变量或部署文件。

## 绑定自己的子域名

1. 先下载现有项目备份，因为不同域名的浏览器存储相互隔离。
2. 在仓库 Settings → Pages 设置自己的子域名，按 GitHub 提示添加 DNS CNAME 并启用 HTTPS。
3. 自定义域名根路径部署时，将 Actions 的 `VITE_BASE_PATH` 仓库变量设为 `/`；保留默认项目站时无需设置。
4. 在新域名导入项目备份。域名无需指向 VPS。

## 主要代码职责

- `src/utils/projectStorage.js`：IndexedDB 草稿、历史及图片事务保存。
- `src/utils/projectAssets.js`：项目格式、素材去重与大小校验。
- `src/utils/projectBackup.js`：项目 ZIP/JSON 导入导出。
- `src/utils/exportPoster.jsx`：按需渲染 PNG。
- `src/utils/historyReducer.js`：纯函数撤销/重做。
- `tests/`：解析、历史、分页、资源等待、模板校验和备份回归测试。

## iPhone 原生应用

仓库内的 `ios/Picmake.xcodeproj` 提供 SwiftUI 项目/卡片编辑、云端保存、历史与模板选择，以及内附海报渲染和系统分享。构建、同步行为与当前功能范围见 [iOS 说明](ios/README.md)。
